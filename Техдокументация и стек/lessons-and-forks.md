# Уроки и развилки miniappgpt — для следующих продуктов

Источник: miniappgpt, реальные инциденты и решения (2026). Статус: **normative**.
Часть А — уроки: инцидент → корень → правило. Часть Б — развилки: где будете
выбирать вы, и что выбрали мы.

---

## Часть А. Уроки (оплачены инцидентами)

### А1. Кэш общего LLM-шлюза отдаёт чужой контекст
**Инцидент.** Под конкуренцией общий LiteLLM-шлюз вернул нашим пользователям
фрагменты ответов **другого арендатора** (названия чужой компании, ФИО).
Корень — кэш ответов на стороне шлюза (вероятно семантический), общий между
tenant'ами. **Правило.** На shared multi-tenant шлюзе каждый запрос несёт
`cache: {"no-cache": true, "no-store": true}` (у нас — автоматически для
провайдера типа litellm). После фикса — верификация нагрузкой: 0 протечек на
серии конкурентных запросов. Инцидент эскалируется владельцу шлюза: кэш между
tenant'ами — их баг, ваш фикс — обход.

### А2. Потолок шлюза меряется, а не читается
**Факт.** Per-key лимит эмбеддингов: ~13–15 rps, причём это **saturation через
очередь** (латентность растёт, 429 нет вплоть до concurrency 30). Латентность
~520 мс/запрос. **Правило.** Перед выбором параллелизма — ступенчатый замер
(стоп на первом 429), а не цифра из доки. Бюджет = произведение уровней
параллелизма (`PROJECT_INGEST_CONCURRENCY × KB_EMBED_CONCURRENCY`) и **делится
с live-запросами пользователей** — фону отдавать не больше половины.

### А3. Зависший воркер не должен держать очередь
**Инцидент.** Завис один ingest-воркер (сетевой вызов без таймаута) → слот
семафора не освободился → вся очередь обработки документов встала; помог только
рестарт. **Правило.** Триада: (1) таймаут на каждый внешний вызов
(`context.WithTimeout`); (2) **watchdog** — слот семафора освобождается по
таймауту даже если воркер жив-завис, задача помечается failed с человеческим
текстом; (3) `RequeueUnfinished` при старте сервиса — подвисшие «pending»
переотправляются. Рестарт перестаёт быть инструментом эксплуатации.

### А4. Grounding: пустой ретрив — это режим, а не исключение
**Инцидент.** Когда ретрив возвращал 0 чанков, запрос уходил в модель «как
есть» — и она уверенно отвечала из общих знаний (галлюцинации в продукте,
который обещает «строго по документам»). Обратная крайность — тупой отказ —
ломала мета-вопросы («о чём этот документ?»). **Правило.** Три режима инжекта:
(1) есть результаты → grounded-промпт с материалом; (2) ноль результатов →
**grounded-refusal промпт + манифест** (список заголовков документов корпуса):
мета-вопросы отвечаются по манифесту, фактические — честный отказ; (3) реранкер
склонен к over-prune (из 60 кандидатов оставлял 0–4) → **backfill floor**:
добирай до минимума (у нас 14) из vector-scored кандидатов.

### А5. Автопамять о пользователе сохраняет не то
**Инцидент 1.** Вопрос «кто такой Владимир Марков?» → инструмент памяти записал
это как **имя пользователя**. **Правило.** У инструмента сохранения профиля —
жёсткий DON'T-список в описании: личные факты сохраняются только если сказаны
пользователем **о себе от первого лица**; вопросы о третьих лицах, содержимое
документов и текст ответов — не факты о пользователе. Плюс негативные примеры
в промпте экстрактора. **Инцидент 2.** Переключение согласия на память
OFF→ON **вычистило все 29 фактов** (revoke = purge по ADR-0003 — поведение
правильное, но неожиданное для пользователя). Спасло то, что purge —
soft-delete: восстановили по `deleted_at`. **Правило.** Деструктивные эффекты
согласий — explicit в UI («отключение удалит сохранённые данные»), purge всегда
soft-delete с retention-окном.

### А6. Каждый «умный» этап — это ещё один LLM-вызов
LLM-реранк добавил второй вызов модели на каждый RAG-запрос: качество выросло,
но пропускная способность чата упала вдвое на том же пуле. **Правило.** Считай
LLM-вызовы на один пользовательский запрос (у нас: реранк + генерация, иногда
+экстрактор памяти) и закладывай в capacity шлюза до релиза, а не после.

### А7. Деплой «прошёл» ≠ конфиг применился
**Инциденты.** (1) Опечатки путей в compose (`./volumes/` vs `./volume/`,
`rafana`) — контейнеры поднялись, но с **дефолтными** конфигами вместо
смонтированных. (2) Алерты ссылались на `job="backend-rest"`, а scrape-job
назывался `miniapp_rest` — правила месяцами «зелёные», потому что матчат **ноль
серий**. (3) После пересоздания контейнеров порты admin/weaviate поменялись
местами (stale Docker NAT) — лечится пересозданием пары сервисов. **Правило.**
После деплоя проверяй **эффект**, а не статус: конфиг внутри контейнера
(`docker exec cat`), алерт матчит >0 серий (`promtool`/API), сервис на порту —
тот, который ожидаешь.

### А8. GitLab: пустой репозиторий с protected default branch
Первый пуш в пустой репо обязан создать default branch, а она protected →
Developer получает reject «Ask a project Owner or Maintainer to create a
default branch» на **любую** ветку. **Правило.** При создании репо сразу:
Owner инициализирует default branch (кнопка «Add README») или роль
Maintainer+. Учитывай при автоматизации синков.

### А9. Ownership проверяется на каждом слое, включая legacy
Аудит нашёл IDOR (A-SEC-01): новый API-слой проверял владельца, **старый
параллельный** — нет; зная id, можно было читать чужие сессии/проекты.
**Правило.** Ownership-предикат — в storage-слое или общем middleware, чтобы
новые и старые роуты не могли его «забыть». Каждый эндпоинт с `:id` — в
регресс-тест на чужой id (403/404).

### А10. Цикл «аудит → фикс-план с ID» работает
Паттерн: полный аудит (ИБ/архитектура/код) → `AUDIT_FIX_PLAN.md`, каждая
находка с ID (`SEC-*`, `COMP-*`, `GO-*`, `FE-*`, `DB-*`, `OPS-*`) и приоритетом
→ ID живут в коммитах/тестах/доках (`// FE-005: …`) → повторный аудит верифицирует
по ID. Находки не теряются, история решений восстанавливается. Бери формат как есть.

### А11. Поведение модели тюнится параметрами раньше, чем промптом
«Сухие» односложные ответы лечились не переписыванием промпта, а
`frequency_penalty` 0.4→0.2 (штраф давил содержательность). Отдельно — защита
от runaway-повторов (зацикливание одной фразы) на стороне бэка. **Правило.**
При странном стиле ответов сначала проверь сэмплинг-параметры по умолчанию
(они — часть продукта и фиксируются в коде, не в чьей-то памяти), потом промпт.

### А12. Тест-раннеры не смешиваются
`vitest run` упал, собрав Playwright-спеки (`test.describe() not expected`).
**Правило.** В каждом vitest-конфиге — `exclude: [...configDefaults.exclude,
"tests/e2e/**"]`; e2e живут в отдельном репо `test` (см. tech-stack §1).

## Грабли-шпаргалка (распечатай)

1. Shared-шлюз → `no-cache` в каждый запрос (А1).
2. Лимиты меряем ступенькой, фону ≤ половины бюджета (А2).
3. Семафор без watchdog = очередь-зомби (А3).
4. Пустой ретрив ≠ свободный микрофон для модели (А4).
5. «Согласие выключил» = purge → предупреди в UI, храни soft-delete (А5).
6. Посчитай LLM-вызовы на запрос ДО релиза (А6).
7. Проверяй эффект конфига, не статус деплоя (А7).
8. Новый GitLab-репо — сначала default branch (А8).
9. Каждый `:id`-эндпоинт — тест на чужой id (А10).
